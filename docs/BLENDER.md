# Blender pipeline

3D assets that need real modelling (currently the intro vault gate) are **generated by Python scripts** in `blender/`, not hand-edited. The script is the source of truth: re-running it rebuilds the scene, the textures, the `.glb` the site loads, and preview renders.

## Build the gate

```bash
"D:/Softwares/blender-5.2.3-windows-x64/blender.exe" --background --factory-startup --python blender/build_gate.py
# skip the Cycles previews (much faster):
"D:/Softwares/blender-5.2.3-windows-x64/blender.exe" --background --factory-startup --python blender/build_gate.py -- --no-render
```

| Output | Used by |
| --- | --- |
| `public/models/gate.glb` | `src/components/gate/GateCanvas.tsx` (Draco geometry + JPEG textures, ~1.2 MB) |
| `blender/gate.blend` | Editable scene with camera, preview lights, textures packed |
| `blender/preview.png`, `preview_open.png` | Cycles stills (closed / half open). Look at them after every change. |
| `blender/textures/` | Generated PNGs (git-ignored; packed into the `.blend` and `.glb`) |

Blender isn't on `PATH` on this machine; use the full path above. Node isn't either: `D:/node-v24.19.0-win-x64/node.exe`.

## The contract with the web code

`GateCanvas.tsx` finds parts **by name** and animates them. Keep these names and pivots when editing:

| Node | Role in the web animation |
| --- | --- |
| `Dial` | Handwheel. Pivot at origin; rotated around Z (three.js) as the visitor drags. Slides with `DoorR` on open. |
| `DoorL`, `DoorR` | Slide ±`DOOR_TRAVEL` (5.0) on X into the wall pockets. Constant must match in both files. |
| `Pin_*` (children of doors) | Retract radially on unlock. |
| `Bolt_0`, `Bolt_1` (children of `DoorR`) | Slide +1.35 on X to release. |
| `SeamGlow` | Light leaking between closed doors; hidden once they part. |
| `StatusLight` | Shares material `Glow` with the seam. |
| material `Glow` | Emissive intensity follows unlock progress. |
| `Wall`, `Frame`, `Chamber` | Static. Chamber is the room the camera pushes into before the fade. |

Coordinates: Blender is Z-up with the gate facing −Y; the exporter converts to Y-up, so in three.js the gate faces +Z.

Everything mounted on a door must stay behind `FACADE_BACK` (y > −0.82) so it slides into the pocket instead of through the wall.

## What makes it look real (and not cartoon)

1. **Microsurface variation.** Flat roughness = plastic. `build_textures()` makes tileable roughness + normal maps with numpy (FFT-shaped noise for smudges, anisotropic noise for brushing, rasterised scratches, pits for concrete). Keep scratches subtle; strong ones read as white lines.
2. **Bevels on every hard edge** (`segments=3`, `harden_normals`). Edges catching light is what reads as "machined".
3. **Consistent texel density.** `Part._box_uv()` box-projects UVs in world space, so every part shares one scale per material (`tile=`).
4. **Depth.** Recessed doorway, pocket doors, interior chamber. Nothing floats in front of a flat wall.
5. **Restrained colour.** Near-black steel and concrete; coral only on the status light, seam and one painted index mark. No emissive "UI" accents on the model.
6. **Lighting in the browser.** Metal is only as good as what it reflects. The web scene uses drei `<Environment>` softboxes, a shadowed spot key, N8AO, a faint coral rim, and film grain + vignette. Without an environment map PBR metal looks black and flat.

## Material recipe the glTF exporter understands

```
Image (Non-Color) → Separate Color (G) → Math Multiply(roughness) → Principled Roughness   ⇒ metallicRoughnessTexture + roughnessFactor
Image (Non-Color) → Normal Map (strength)                       → Principled Normal      ⇒ normalTexture + scale
```

Pack the roughness image glTF-style (R = 1, G = roughness, B = 1): glTF reads metalness from B, so a grey image would scale the metallic factor down.

Inspect an export with `node .claude/skills/blender-asset/inspect-glb.mjs public/models/gate.glb` (prints materials, texture slots, image sizes and node names).

## Verify

1. Look at `preview.png` / `preview_open.png`.
2. `npm run build`, then load the site and turn the wheel. Check the doors clear the opening and the dial follows `DoorR`.
3. Keep the `.glb` small (target ≤ 1.5 MB). Raise `TEX_SIZE` only if you can see the difference.
